# 실행 스크립트가 지켜야 할 것

> 손으로 치지 않고 스크립트로 돌리는 이유는 하나다 — 인자를 하나 빠뜨려도 프로그램은
> 기본값으로 돌아버리고, 종료 코드를 사람이 눈으로 보면 `1` 과 `2` 의 차이가 묻힌다.

이 문서는 그 스크립트가 기댈 것을 정한다. **여기 적힌 것만 계약이다.** 화면에 찍히는
문구나 표의 모양은 언제든 바뀌므로 파싱하지 마라.

---

## 1. 어디에 두나

```
작업 폴더/
  run_daily.sh        ← 여기
  configs/env.yaml    ← 설정
  outputs/            ← 결과가 쌓이는 곳
  <프로그램>/          ← ✗ 여기 안에는 아무것도 두지 마라
```

**프로그램 디렉터리 안에는 아무것도 두지 마라.** 갱신할 때 통째로 갈아끼우므로
안에 둔 것은 사라진다. 스크립트도 설정도 노트북도 전부 작업 폴더 직하다.

실행 위치도 작업 폴더가 기준이다 — 상대 경로가 전부 거기서 풀린다.

## 2. 무엇을 부르나

```bash
python <프로그램>/src/run.py [옵션]
```

`PYTHONPATH` 도 설치도 필요 없다. 파이썬이 스크립트가 있는 디렉터리를 `sys.path[0]` 로
잡으므로 패키지가 그대로 import 된다. **공용 venv 에 이 패키지를 설치하지 마라** —
남기면 디렉터리를 갈아끼울 때 옛 사본이 조용히 먼저 잡힌다.

## 3. 종료 코드 — 여기에 분기한다

| | 뜻 | 스크립트가 할 일 |
|---|---|---|
| `0` | 정상 | 다음으로 |
| `1` | **돌았지만 온전치 않다** (계약 위반) | 재시도해도 같다. 사람이 본다 |
| `2` | **시작도 못 했다** (인자 누락, 입력 없음) | 고치고 다시 돌린다 |

`1` 과 `2` 를 가르는 기준은 **"계산을 시작했나"** 다. 둘을 같게 취급하면 고치면 되는
것과 사람이 봐야 하는 것이 섞인다.

```bash
#!/usr/bin/env bash
set -uo pipefail          # -e 는 쓰지 마라. 종료 코드를 직접 봐야 한다

python "$PROG/src/run.py" --data "$1" | tee "outputs/$(date +%F).log"
code=${PIPESTATUS[0]}

case $code in
  0) echo "OK" ;;
  1) echo "계약 위반 — 리포트의 contract 줄을 옮겨 적을 것" ;;
  2) echo "시작 못 함 — 인자·경로 확인" ; exit 2 ;;
esac
```

## 4. 출력 스트림

**RUN SUMMARY 는 stdout, 진행 상황은 stderr 로 간다.** 그래서 `> log.txt` 로 요약만
깨끗이 남길 수 있고, 사람은 도는 동안 stderr 를 본다.

`tee` 를 쓸 때는 `$?` 가 `tee` 의 것이 되므로 **`${PIPESTATUS[0]}`** 를 봐야 한다.
이걸 놓치면 프로그램이 무슨 코드로 죽든 항상 `0` 이 된다.

## 5. 인자를 스크립트에 박아라

스크립트의 존재 이유가 이것이다. 매번 손으로 치면 언젠가 하나를 빠뜨리고, 프로그램은
**죽지 않고 기본값으로 돈다.** 그러면 실패가 아니라 *다른 결과*가 나오고, 그건 화면만
봐서는 알 수 없다.

바뀌는 것(날짜, 입력 경로)만 인자로 받고 나머지는 스크립트에 고정한다.

## 6. 결과는 `outputs/` 로

프로그램 디렉터리 안에 쓰면 갱신할 때 사라진다. 상대 경로는 작업 폴더 기준으로 풀리므로
`outputs/` 라고만 적으면 맞아떨어진다.

**작업 폴더의 `.gitignore` 에 `outputs/` 를 넣었는지 확인하라** — 안 넣으면 결과가
그대로 커밋된다.
