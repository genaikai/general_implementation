## 개요

**기능 개발은 개발 장비에서, 검증은 운영 장비에서.** 두 곳을 오갈 수 없는 환경에서
그 분리를 사람의 규율이 아니라 코드 구조로 강제하기 위한 스캐폴드다.

```
[개발 장비] 구현 ──이식──▶ [운영 환경] 실험 ──인사이트──▶ [개발 장비] 개선 ──▶ …
```

풀려는 문제는 이렇다. 운영 데이터는 밖으로 못 나오고, 결과 파일도 못 가져오고,
저쪽에서는 코드를 고칠 수도 LLM을 쓸 수도 없다. 그래서 **데이터 없이 짜고, 통째로
보내고, 화면만 보고, 사람이 배운 것만 들고 나온다.**

| | |
|---|---|
| `{BB}` | 개발 장비의 저장소 — **이 저장소** |
| `{AA}` | 운영 장비의 작업 폴더 |

---

## 역할

- [운영 환경]
데이터 처리 로직, 입력에 필요한 데이터 전처리, 데이터 준비

- [개발 장비]
'운영 환경'에서 입력으로 받을 데이터 포맷을 기반으로 기능 개발
출력 데이터 생성
'운영 환경'에서 해당 기능 개발에 대한 코드 수정 금지

## 이식 방법 (운영 환경)

```bash
cd {AA}/{target_path}
git clone <원격> .staging/{BB}           # 최초 1회만
bash .staging/{BB}/scripts/sync.sh v{tag_version}  # 매번 (ex. v0.15)
```
위 실행 이후, {AA}/{target_path}/{BB} 위치로 해당 tag 버전에 해당하는 코드가 생성/업데이트 된다.

# 파일별 — 무엇을 담고 무엇을 담지 않나

프로젝트를 시작할 때 **어느 파일에 무엇을 쓰는가**의 기준이다. "담지 않는 것" 쪽이
더 중요하다 — 이 구조가 막으려는 사고는 대부분 내용이 엉뚱한 파일에 들어가서 난다.

```
src/run.py          진입점 — venv 갈아타기 + 위임. 그 외 아무것도
src/<pkg>/
  __main__.py       실행 흐름 — 인자 파싱, 순서, 종료 코드
  contracts.py      ★ 입력 계약. 프로젝트에서 제일 먼저 고치는 파일
  synth.py          계약에서 파생한 가짜 데이터
  load.py           포맷을 아는 유일한 곳
  pipeline.py       도메인 로직
  report.py         RUN SUMMARY 렌더링
tests/              계약 왕복 + 규격 자체 검사
configs/            설정 예시 (실값은 {AA} 에만)
```

---

## `src/<pkg>/contracts.py` — 이 프로젝트의 중심

**담는 것.** `INPUT_SCHEMA` 하나. 필드마다 이름·타입·널 허용·허용값·범위, 그리고
운영 환경에서 확인한 사실을 적는 `note`, 처리 로직이 읽는지를 나타내는 `used`.

```python
Field("customer_id", "str", False, note="영문+숫자 12자리")
Field("amount", "float", True, rng=(0.0, 1e12))
Field("grade", "category", True, allowed=("A", "B", "C"))
Field("legacy_memo", "str", True, used=False)   # 안 읽는 필드 → 노트로 강등
```

**담지 않는 것.** 실제 값, 분포, 식별 가능한 코드값 목록. 구조만 적는다 (C3).
`allowed=("A","B","C")` 는 구조지만, 실제 등급 코드 40개를 나열하면 그건 데이터다.

**왜 여기 하나뿐인가.** 운영 환경에서 회수되는 정보의 절반이 "입력 포맷"이다(C5).
그게 도착할 지점이 코드 안에 한 곳이어야 반영이 싸다. 여기를 고치면 `synth.py`·
검증·리포트·테스트가 **전부 따라온다.**

> 운영 환경 실험에서 얻은 사실은 반드시 여기로 돌아온다. `note` 에 "2026-08 확인:
> 12자리 아니고 14자리도 있음" 처럼 날짜와 함께 남긴다.

## `src/<pkg>/synth.py` — 가짜 데이터는 파일이 아니라 코드다

**담는 것.** `generate(n, seed, mode)` — 계약을 읽어 런타임에 데이터를 만든다.
그리고 `_corrupt()` 에 **운영 환경에서 실제로 터진 사고 유형**을 모은다.

```python
kind 0  숫자 컬럼이 "1,234" 로 읽힘        # 천 단위 쉼표
kind 1  계약에 없는 카테고리 값 "?" 
kind 2  nullable=False 인데 빈 값
kind 3  대소문자·앞뒤 공백 흔들림 " c "
kind 4  범위 밖 "-1"
```

**담지 않는 것.** 파일을 읽는 코드. 픽스처 경로. 실데이터에서 뜬 실제 값.

**왜 코드인가.** `.gitignore` 는 `git add -f` 한 번에 뚫리지만 **없는 파일은 올라갈
수 없다**(C6). 테스트도 픽스처 파일 대신 `generate()` 를 부른다 — 덤으로 계약이
바뀌면 테스트 데이터가 저절로 따라 바뀐다.

> 운영 환경에서 새 사고 유형을 만나면 **여기에 추가한다.** 그러면 다음부터는
> 개발 장비에서 미리 터진다. 이게 §4 되돌리기 고리의 실체다.

## `src/<pkg>/load.py` — 포맷을 아는 유일한 곳

**담는 것.** 입력을 읽어 `list[dict]` 로 만드는 코드. CSV 파싱, 인코딩(BOM), 널 토큰,
구분자, 압축 해제 — **포맷에 대해 아는 모든 것**이 여기 모인다.

**담지 않는 것.** 도메인 판단. 필터링 기준. 지표 계산.

**왜 가르나.** 운영 환경에서는 한 줄도 못 고친다(C2). 실데이터가 예상과 다른 포맷이면
고쳐야 할 곳이 **이 파일 하나**여야 다음 사이클이 싸다. 처리 로직이 포맷을 알면
포맷이 바뀔 때 손댈 곳이 사방으로 번진다.

## `src/<pkg>/pipeline.py` — 도메인 로직

**담는 것.** 실제로 하려는 계산. 지표 산출, 모델 추론, 집계.

**담지 않는 것.** 파일 경로, 임계값, 하이퍼파라미터 같은 **바뀔 만한 값**(§1.3).
전부 인자로 받는다 — 운영 환경에서 "이 값만 고치면 되는데" 하는 순간이 오면 그건
이미 규칙이 깨진 것이고, 고치지 말고 **인사이트로 들고 나온다.**

**지표 이름은 사이클 사이에 바꾸지 않는다.** 이름이 바뀌면 지난 사이클 숫자와 대조할
수 없고, 반출이 안 되는 환경에서 그건 되돌릴 수 없는 손실이다.

## `src/<pkg>/report.py` — 화면이 유일한 출력이다

**담는 것.** RUN SUMMARY 블록 렌더링. 한 줄에 한 항목, **80칸**(글자 수가 아니라
표시 폭 — 한글은 두 칸) 이내.

**담지 않는 것.** 실데이터의 개별 값·식별자(C3). 파일 쓰기.

**옮겨 적기 좋게 쓰는 것이 전부다.** C4로 파일 반출이 안 되므로 사람이 손으로 베낀다.

- `args` 를 그대로 한 줄 — 이 줄만 옮기면 재현된다
- 계약 위반은 필드명과 함께 한 줄씩. **`validation failed` 는 이 규격에서 결함이다**
- `version` 은 절대 빈칸이 아니다. 모르면 `unversioned`
- 노트(안 읽는 필드의 어긋남)는 위반과 **가른다** — 섞으면 매 실행마다 뜨는 줄이
  생기고, 사람은 곧 `contract` 줄 자체를 안 보게 된다

## `src/<pkg>/__main__.py` — 실행 흐름

**담는 것.** `argparse` 정의, 실행 순서(적재 → 검증 → 처리 → 리포트), 종료 코드.

**담지 않는 것.** 도메인 계산. 포맷 파싱. 렌더링.

**조기 실패가 규칙이다.** 필수 인자가 빠지면 **어떤 계산도 하기 전에** 죽는다 —
30분 돌린 뒤 인자 하나 때문에 죽으면 사이클 하나를 통째로 버린다.

| 종료 코드 | 뜻 | 스크립트가 할 일 |
|---|---|---|
| `0` | 정상 | 다음으로 |
| `1` | 돌았지만 온전치 않다 (계약 위반) | 재시도해도 같다. 사람이 본다 |
| `2` | 시작도 못 했다 (인자·입력·설정) | 고치고 다시 돌린다 |

**RUN SUMMARY 는 stdout, 진행 상황은 stderr.** 요약이 stderr 로 새면 `> log.txt` 가
빈다.

## `src/run.py` — 진입점

**담는 것.** 두 가지뿐. `paths.venv` 설정을 보고 그 파이썬으로 `os.execv` 하는 것,
그리고 `<pkg>.__main__.main` 으로 넘기는 것.

**담지 않는 것.** 그 외 전부. 로직이 여기 쌓이면 `src/` 가 평평해지고, `contracts`·
`report` 같은 흔한 이름이 최상위 모듈이 되어 서드파티를 가린다.

**왜 venv 를 갈아타나.** 공용 venv 가 여럿인 환경에서 activate 를 잊고 돌면 실패가
아니라 **다른 결과**가 나온다. 설정에 적어만 두고 쓰지 않으면 "설정했는데 무시된다"가
되고, **설정 파일의 값이 아무것도 바꾸지 않는 것은 그 자체로 결함이다.**

## `tests/` — 규격을 잠그는 자리

| 파일 | 담는 것 |
|---|---|
| `test_contracts.py` | 계약↔생성기 왕복, 결정론, 위반 메시지가 필드명을 담는지 |
| `test_run.py` | 전 구간 스모크, 종료 코드, 스트림 분리, 80칸, 한글 정렬 |
| `test_spec_compliance.py` | **코드가 아니라 규격 자체** — `git archive` 를 풀어 이식 표면을 검사 |

**픽스처 파일을 두지 않는다.** `generate()` 를 부른다.

**API 키 없이 전부 통과해야 한다.** 운영 환경 실행 가능성을 개발 장비에서 기계적으로
확인하는 유일한 방법이다.

```bash
env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY python -m pytest
```

> **되돌리기의 종착점이 여기다.** 운영 환경에서 배운 것을 인사이트 파일에 적는 것은
> *포착*이고, 규칙으로 굳은 것을 테스트로 옮기는 것이 *고정*이다. 관찰 날짜와 규모를
> 독스트링에 남기면 그 테스트가 깨질 때 근거가 같이 나온다 —
> `"""운영 로그의 prev_question 은 list 다 (2026-09-01, 16,141건)."""`

## `configs/env.example.yaml` — 예시만 커밋된다

**담는 것.** 키의 목록과 각 키가 무엇인지. 값은 비워둔다.

**담지 않는 것.** 운영 실값. 접속 정보. 경로. 그건 `{AA}/configs/env.yaml` 에만 있고
저장소로 오지 않는다(C3).

`sync.sh` 가 **없을 때만** 복사하므로 한번 채운 실값은 다음 sync 에 덮이지 않고,
example 에만 있는 새 키는 경고로 알려준다. CLI 인자만 쓰는 프로젝트면 `configs/` 를
통째로 지워도 된다.

## `requirements.txt` / `requirements-dev.txt`

| | 담는 것 | 이식 |
|---|---|:--:|
| `requirements.txt` | 운영 환경에서 실제로 필요한 것만. **버전 고정** | ✔ |
| `requirements-dev.txt` | `pytest`, `anthropic` 등 개발 장비 전용 | ✗ |

**가르는 이유가 C7·C8이다.** 운영 venv 는 공용이라 남의 환경을 깨뜨릴 수 없고,
LLM SDK 는 저쪽에서 어차피 못 쓴다. 버전을 고정하는 것은 두 환경이 같은 것을 쓰게
하는 잠금 파일이기 때문이다.

## `.gitignore` / `.gitattributes` — 경계 두 겹

| | 하는 일 |
|---|---|
| `.gitignore` | 저장소에 **애초에 들어오지 못하게** — 데이터·산출물·로컬 설정 |
| `.gitattributes` 의 `export-ignore` | 저장소에는 두되 **archive 결과에서 뺀다** — 개발 전용 |

**`.gitignore` 는 allowlist 로 쓴다.** 막을 것을 이름으로 나열하면 오타 한 번에 무시가
풀리고 그때 조용히 커밋된다. `configs/*.yaml` 로 통째 막고 `!configs/env.example.yaml`
로 예외를 명시한다.

**`.gitattributes` 에 줄 끝 주석을 쓰지 마라.** git 이 지원하지 않는다. 패턴 뒤의 모든
토큰을 속성 이름으로 읽어서 `tools/ export-ignore  # 설명` 은 경고 한 줄만 내고
**그 줄이 통째로 무시된다.** 설명은 앞 줄에 단다.

**아직 없는 파일도 미리 적어둔다.** 나중에 하나 생겼을 때 줄이 없으면 조용히 넘어가고,
그건 사본을 지우고 태그를 다시 내야 하는 사고다.

## `tools/` — 개발 보조 도구 (이식 ✗)

**담는 것.** LLM·외부 API 를 쓰는 것. 계약 리뷰, 프롬프트 실험, 데이터 탐색 도구.

**규칙은 하나, import 방향이다.** `tools/` 는 `src/` 를 읽어도 되지만
**`src/` 는 `tools/` 를 import 하지 않는다.** 위치보다 이 규칙이 실제 사고를 막는다.

두 번 이상 쓸 것이면 커밋하고(도구도 자산이다), 한 번 쓰고 버릴 것이면 커밋하지 않는다.

## 문서 넷 — 성격으로 가른다

| | 누가 읽나 | 이식 |
|---|---|:--:|
| `README.md` | 이 저장소를 쓰는 사람 + **사본을 받아든 사람** | ✔ |
| `TODO.md` | `{AA}` 에서 **무엇이 남았나**만 센다 | ✔ |
| `todo/*.md` | 그것들을 **어떻게 만드나**의 규격 | ✔ |
| `docs/*.md` | 이 프로그램이 **어떻게 도는지**. 결과를 읽는 쪽이 본다 | ✔ |
| `docs/insights/` | 운영 환경에서 **가져온** 기록. 되돌아가지 않는다 | ✗ |
| `IMPLEMENTATION_SPEC.md` | **왜 그런가** — 제약 C1–C8 과 도출 | ✗ |

**규격 문서는 이식되지 않는다.** 그래서 `{AA}` 에서 필요한 것은 README 와 `TODO.md` 에
있어야 한다.

**`TODO.md` 는 방법을 베끼지 않는다.** 만드는 법은 `todo/` 에 두고 가리키기만 한다 —
베끼면 둘이 갈라지고, 갈라진 쪽을 보고 만들면 어긋난 것이 나온다.

**`docs/insights/` 에는 실험 직후에 적는다.** 사람 머릿속을 거치는 유일한 고리라 가장
잘 샌다. 계약 위반 전문, 새 사고 유형, "코드 고치고 싶었던 순간", 의존성 충돌 메시지.
